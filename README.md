# powcon-plus

Power and energy monitoring for a workstation, based on the data reported by
a **Corsair HX1200i** power supply, exposed by the kernel `corsairpsu` driver
through hwmon.

The program stays resident: it publishes power and daily energy next to the
tray icon, integrates the day's watt-hours and keeps them on disk. A detail
window provides a live chart, rail voltages, temperatures and a per-day
summary.

In the GNOME top bar the label takes a form such as `148 W · 2.4 kWh`.

## Requirements

- Linux with the `corsairpsu` kernel module (present in recent kernels) and
  the power supply's USB cable connected. The prerequisite is verified with
  `sensors`: the chip `corsairpsu-hid-3-4` must be listed.
- Go 1.24 or newer to build (developed and tested with 1.26).
- A system tray implementing the StatusNotifierItem protocol: GNOME with the
  AppIndicator extension (already enabled on Ubuntu,
  `ubuntu-appindicators@ubuntu.com`), KDE, XFCE, Hyprland, swaybar.
- The detail window alone requires the OpenGL/X11 libraries:
  `libgl1-mesa-dev`, `libx11-dev`, `libxcursor-dev`, `libxrandr-dev`,
  `libxinerama-dev`, `libxkbcommon-dev`.

## Checking the dependencies

```bash
powcon-plus check            # sensor, session bus, tray host, GUI libraries
powcon-plus check --build    # also the toolchain needed to compile
```

The check probes the host and, for anything missing, prints the command that
installs or enables it; the package manager is detected automatically (apt,
dnf, pacman, zypper). The GUI libraries are read from the built binary through
the loader, so the report reflects what that binary actually needs.

Findings marked `missing*` are essential: the command exits with a non-zero
status when one is present, so a script can stop on it. Everything else is a
warning — the daemon and the tray work without the window libraries.

## Build and start

```bash
make all                    # bin/powcon-plus + bin/powcon-plus-gui
./bin/powcon-plus-gui run   # daemon with tray icon
```

Running `make` with no arguments prints the available targets.

Commands that are useful while testing:

```bash
./bin/powcon-plus status           # immediate reading, works without a daemon too
./bin/powcon-plus report --days 7  # kWh and cost per day
./bin/powcon-plus window           # detail window
./bin/powcon-plus run --no-tray    # data collection only, no icon
./bin/powcon-plus version          # installed version
```

## Tray icon

| Interaction | Effect |
|---|---|
| Left click | opens the detail window |
| Middle click or scroll wheel | cycles the label content: power, energy of the day, both, icon only |
| Right click | menu: window, label, alert threshold, autostart, quit |

The label next to the icon uses the Ayatana property `XAyatanaLabel`. On
GNOME/Ubuntu and KDE it is always visible; on other compositors it may appear
in the tooltip only. In that case set `label_mode = "none"` and read the
tooltip.

The icon is generated by the program (a lightning bolt) and takes a different
colour depending on whether collection is active, suspended, or the sensor has
been lost. Alternatively a theme icon can be used by setting
`icon_mode = "name"` and `icon_name` (for example `powersupply`); in that mode
the icon no longer changes colour with the state.

## Detail window

The top bar contains, from the left: the pause/resume collection button, the
selector for the tray label content, the autostart checkbox, the language
selector, the cost-per-kWh field with its currency selector, the Info button
(version and developer), Report, Quit.

Below the bar are the daemon status, the current power reading, a chart of the
last 30 minutes, the rail voltages and temperatures, the fan, and the table of
days.

The reported cost is an estimate: the tariff is entered by the user in the
cost-per-kWh field. The currency selector (EUR, USD, GBP, CNY, JPY) determines
only the symbol and the label of the value, with no currency conversion. The
entered value is persisted in the configuration.

Pausing collection is available only in the window. It was removed from the
tray menu because the GNOME AppIndicator extension does not refresh menu
labels, which would therefore stay inconsistent with the actual state. The
state change remains visible through the icon colour.

## Autostart

It is enabled from the detail window or from the tray menu entry, or from the
command line:

```bash
powcon-plus autostart-status
powcon-plus install-autostart      # writes ~/.config/autostart/powcon-plus.desktop
powcon-plus uninstall-autostart
```

The desktop entry is written pointing at the executable in use at that moment,
so it stays consistent after a binary update. The XDG entry starts with the
graphical session, which is the condition the tray icon requires.

A systemd user unit is available instead with `--mode systemd`, attached to
`graphical-session.target`; its logs are read with
`journalctl --user -u powcon-plus`. A flock prevents more than one instance
from starting.

## Installation

```bash
make install    # copies both binaries into ~/.local/bin
```

`powcon-plus` is the daemon built without cgo, small and portable.
`powcon-plus-gui` is the same program built with the `gui` tag, which also
includes the window: it is the binary to use for autostart, since a single
executable serves as both daemon and window.

Uninstalling:

```bash
powcon-plus uninstall          # stops the daemon, removes autostart and binaries
powcon-plus uninstall --purge  # also removes data and configuration
```

Without `--purge`, data and configuration are kept, so a later installation
finds the history again.

## Configuration

The file is `~/.config/powcon-plus/config.toml`, generated with
`powcon-plus init-config`. The complete list of keys with descriptions is in
[docs/config.example.toml](docs/config.example.toml). The most relevant ones:

```toml
label_mode = "power"        # power | energy | both | none
poll_interval = "1s"        # below 200ms makes no sense: the PSU aggregates over ~1s
price_per_kwh = 0.25        # tariff used for the cost estimate
currency = ""               # EUR | USD | GBP | CNY | JPY; empty = follows the language
alert_power_w = 800         # notification after a sustained breach of the threshold (0 = off)
alert_sustain = "15s"
sample_store = true         # false = no history written at all
sample_interval = "10s"
retention_days = 31         # days of raw samples to keep
data_dir = ""               # empty = ~/.local/share/powcon-plus
sensor = ""                 # empty = auto-detect; e.g. "hwmon8" to force one
language = ""               # it | en | de | fr | es | zh | ja; empty = from the locale
```

With `label_mode = "both"` the label takes a form such as `148 W · 2.41 kWh`;
with `energy`, below 1 kWh, watt-hours are shown instead (`340 Wh`).

The language applies to the window, the tray menu and the notifications. When
the field is empty it is determined from the system locale, falling back to
English. It can be changed live from the selector in the window; the choice is
saved to the configuration.

With `sample_store = false` no history file is written: the folder holds only
the lock and the socket. The table and the report therefore show the current
session only.

## Files produced

```
~/.local/share/powcon-plus/daily.json                 per-day summaries
~/.local/share/powcon-plus/samples-2026-09-30.jsonl   raw samples, one file per day
~/.local/share/powcon-plus/control.sock               daemon control socket
```

Examples of analysis:

```bash
jq -s 'map(.w) | add/length' ~/.local/share/powcon-plus/samples-$(date +%F).jsonl
powcon-plus report --csv | column -t -s,
```

## Architecture

Reading happens from `/sys/class/hwmon/hwmonN` where `name = corsairpsu`. The
channels are resolved from the **labels** exposed by the driver rather than
from indices, which change between versions of the driver itself.

The power supply exposes no energy counter: watt-hours are integrated from
power using the trapezoidal rule. Gaps between two readings larger than
`3 × poll_interval` are excluded from the integration, so that a suspended PC
is not credited with energy it did not draw.

The daemon uses no cgo: the tray and the notifications go through D-Bus
(`StatusNotifierItem` and `DBusMenu`), which keeps the binary small and
cross-compilable. The window is built with Fyne and requires the `gui` build
tag.

The version is defined in `internal/version`, the single source for the
`powcon-plus version` command and for the window's Info dialog.

## Troubleshooting

| Symptom | Most likely cause |
|---|---|
| `corsairpsu sensor unavailable` | USB cable unplugged, module not loaded, or OpenLinkHub/liquidctl/iCUE has taken over the device (in which case the hwmon node disappears) |
| Icon missing while the daemon runs | AppIndicator extension disabled, or a session without a graphical bus (ssh, global systemd service) |
| Label not visible in the bar | desktop without `XAyatanaLabel` support: set `label_mode = "none"` and use the tooltip |
| `daemon not running` from the `ctl` commands | check that the daemon is running and the permissions on `~/.local/share/powcon-plus/control.sock` |
| Inconsistent readings or concurrent device access | more than one daemon instance: the flock should prevent it, verify with `pgrep -af powcon-plus` |
